For the Coding Round , focus on Concurrency and Advanced Data Structures. Recent reports from MongoDB Senior Engineer interviews (2025–2026) show a consistent pattern: they want to see how you handle data consistency and thread safety in Java.
Here is your targeted practice list:

1. The Concurrency "Must-Haves"
MongoDB is a high-concurrency database. They often ask you to implement classic synchronization primitives or data structures from scratch to test your understanding of the Java Memory Model.
* Implement a Read-Write Lock: Practice this using ReentrantLock and Condition variables.
* Thread-Safe Bounded Blocking Queue: Don't just use LinkedBlockingQueue; know how to implement it using wait/notify or Lock/Condition.
* Rate Limiter: A frequent question for AI-focused teams. Implement a "Token Bucket" or "Leaking Bucket" algorithm that is thread-safe.
2. High-Frequency LeetCode Style Patterns
Based on recent feedback, focus on these specific types:
* String/Word Problems: Word Break (I & II) is a classic MongoDB favorite. It tests your ability to use DP or Recursion with Memoization.

3. Java Specifics they will "Grill" you on
Expect these follow-up questions during or after the coding:
* Synchronized vs. ReentrantLock: Why choose one over the other? (Hint: tryLock, fairness, and multiple conditions).
* Java Streams vs. For-loops: When is a Stream less efficient? How do parallel streams work under the hood (ForkJoinPool)?
* Memory Management: Be ready to explain how your code avoids Memory Leaks and how it impacts the Garbage Collector (ZGC/G1GC).

Machine Coding / LLD (The "Modular" Round)
In this round, you are expected to write working, thread-safe, and extensible code. Given your team's focus, the problem will likely involve resource management or data pipelines.
Likely Scenarios:
* The In-Memory Vector Store: Implement a system where you can add "Vectors" (arrays of floats) and find the top $K$ most similar ones using Euclidean distance or Cosine Similarity.
* The Distributed Task Orchestrator: Design a system that takes "AI Jobs" (like generating an embedding), assigns them to workers, handles retries, and maintains status.
* Multi-Level Cache for AI Prompts: A thread-safe cache with a size limit and an eviction policy (LRU/LFU).

What they look for in your Java code:
* Concurrency: Heavy use of CompletableFuture, ReentrantLock, or ConcurrentHashMap. Avoid simple synchronized blocks if a more granular lock is possible.
* Design Patterns: * Strategy Pattern: For switching between different similarity algorithms (Cosine vs. Euclidean).
    * Observer Pattern: For notifying services when an embedding job is complete.
* Edge Cases: What happens if the LLM API is slow? How do you handle a "poison pill" task?

Design a ReadWriteLock class that controls access to a shared resource.
The lock must satisfy the following rules:
1. Multiple threads may hold a read lock at the same time, provided no thread holds a write lock.
2. Only one thread may hold a write lock at any moment. While a write lock is held, no other thread (reader or writer) can acquire any lock.
Your class should expose four methods:
* acquireReadLock(): blocks until the lock can be granted for reading.
* releaseReadLock(): releases a previously acquired read lock.
* acquireWriteLock(): blocks until the lock can be granted for writing, i.e., all existing read and write locks have been released.
* releaseWriteLock(): releases a previously acquired write lock.
The implementation must avoid deadlocks and race conditions and should be safe for use by multiple concurrent threads.
